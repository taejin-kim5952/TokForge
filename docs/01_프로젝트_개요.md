# 1. 프로젝트 개요

## 한 줄 정의

> **TokForge — VSCode + Continue.dev 같은 AI 에이전트와 LLM 사이에서 동작하는 컨텍스트 최적화 미들웨어.
> 정제·캐시·RAG·압축·템플릿·라우팅 6단계를 거치되, 각 단계의 프롬프트와 동작을 **프로젝트마다 다르게 튜닝**해 답변 품질과 토큰 효율을 동시에 끌어올린다.**

> **토큰 절감 = 외부 API 면 비용, 로컬 LLM 이면 속도·자원**.
> 백엔드와 무관하게 가치를 만드는 것이 TokForge 의 설계 원칙.

## 미션

> 프로젝트마다 다른 컨텍스트 전략으로 답변 품질을 높이고 토큰을 절감하며,
> 흐름과 통계 시각화로 지속 개선한다.

## 왜 만드는가 — 문제 정의

| 현재 AI 코딩 워크플로의 문제 | TokForge 의 해법 |
|---|---|
| 같은 질문을 매번 새로 호출 → 토큰 낭비 | **의미 캐시** — 비슷한 질문 즉시 응답 |
| 회사 코드/문서 컨텍스트 없음 → 환각 | **RAG** — 사내 문서 자동 검색·주입 |
| 프롬프트 품질 들쭉날쭉 → 답변 불안정 | **템플릿화** — 일관된 형식 강제 |
| 짧고 모호한 질문 → 헛다리 답변 | **질문 정제** — LLM 으로 의도 명확화 |
| 긴 컨텍스트 → 토큰 비용 폭증 | **압축** — 핵심만 추출 |
| 모든 질문에 비싼 모델 사용 → 과지출 | **모델 라우팅** — 복잡도 따라 자동 선택 |
| 프롬프트 한 번 정하면 코드 수정 + 재기동 필요 | **DB 기반 프롬프트 버전 관리** — Admin UI에서 즉시 교체 |
| 모두가 같은 프롬프트 — 프로젝트별 차별화 X | **프로젝트별 격리** — 자기 컨텍스트로 작업 |
| 토큰/비용 가시성 부족 → 개선 불가 | **자체 모니터링** — SQLite + Admin Dashboard |

## 처리 파이프라인

```
[사용자 질문]
    ↓
[1] 정제 (gemma3:1b)         오타·중복 제거, 의도 명확화
    ↓
[2] 의미 캐시 lookup           같은/비슷 질문 → 즉시 응답
    ↓ (캐시 미스)
[3] RAG 검색                   관련 문서 chunk top-k 추출
    ↓
[4] 압축 (gemma4:latest)       핵심만 남기고 토큰 줄이기
    ↓
[5] 프롬프트 템플릿            system 메시지 + context 조립
    ↓
[6] 모델 라우팅 (gemma4:latest) 복잡도 → simple/medium/complex 모델 선택
    ↓
[Ollama 호출]
    ↓
[응답]
    ↓
[7] 캐시 저장 + 모니터링 기록  요청별 메트릭스 SQLite 저장
    ↓
[8] (선택) Langfuse trace 전송
    ↓
[사용자]
```

각 단계의 프롬프트는 DB(`prompts` 테이블)에 저장되고 Admin UI에서 무재기동 교체 가능.

### 전체 위치

```
┌─────────────────┐       ┌──────────────┐       ┌──────────────────┐
│  VSCode         │       │  TokForge    │       │  Ollama (로컬)    │
│  + Continue.dev │ ────▶ │  (FastAPI)   │ ────▶ │  gemma3 / gemma4 │
│  + 브라우저 UI   │       │  port: 8000  │       │  port: 11434     │
└─────────────────┘       └──────────────┘       └──────────────────┘
                                 │
                                 ▼
                          ┌──────────────────┐
                          │  storage/        │
                          │  - monitor.db    │  (users/sessions/projects/prompts/requests)
                          │  - cache.db      │
                          │  - cache.faiss   │
                          └──────────────────┘

                                 ▲
                                 │ OAuth dance
                                 ▼
                          ┌──────────────────┐
                          │  Google OAuth    │
                          └──────────────────┘
```

### 백엔드 레이어 (Layer 책임 분리)

```
TokForge/
├── main.py                     진입점 (FastAPI 앱 + 라우터 등록 + DB init)
└── app/
    ├── config.py               전역 설정 + .env 로드
    ├── db.py                   SQLite 공통 connection (PRAGMA foreign_keys=ON)
    ├── api/                    🌐 HTTP 인터페이스 (Java Controller)
    │   ├── health, chat, models, cache, rag
    │   ├── prompt, refiner, compressor, router
    │   ├── monitor, admin
    │   ├── auth                ← Google OAuth + /me + /logout
    │   ├── projects            ← 사용자별 프로젝트 CRUD
    │   └── deps                ← CurrentUser dependency
    ├── services/               🧠 비즈니스 로직 + Repository
    │   ├── cache, rag                      (의미 캐시, RAG)
    │   ├── refiner, compressor, router     (LLM 호출 서비스)
    │   ├── prompt                          (템플릿 조립)
    │   ├── monitor, pricing                (모니터링)
    │   ├── prompt_repo                     (프롬프트 버전 관리 DB)
    │   ├── user_repo, session_repo         (인증 관련 DB)
    │   └── project_repo                    (프로젝트 DB)
    ├── llm/                    🤖 외부 LLM 호출
    │   └── ollama
    └── observability/          📡 트레이싱 (선택)
        └── langfuse_client
```

| 레이어 | 책임 | Java 비유 |
|---|---|---|
| `api/` | HTTP 경로 + 요청/응답 변환 | Controller |
| `services/` | 핵심 로직 + Repository | Service + Repository |
| `llm/` | 외부 LLM API 호출 | RestClient |
| `db.py` | SQLite 공통 connection | DataSource |

→ 한 기능을 수정할 때 **3-4 레이어만** 보면 됨 (api → service/repo → db → llm).

## 주요 의존성

| 라이브러리 | 용도 | 단계 |
|---|---|---|
| `fastapi` + `uvicorn` | 웹 서버 | 1 |
| `httpx` | Ollama / Google API 호출 | 1 |
| `sentence-transformers` + `faiss-cpu` | 의미 캐시 / RAG 벡터 | 2-3 |
| `langchain` + `langchain-huggingface` | 프롬프트 템플릿, RAG | 3-7 |
| `python-dotenv` | .env 로드 | 모든 단계 |
| `authlib` + `itsdangerous` | Google OAuth + PKCE + JWKS | 운영 |
| `langfuse` (선택) | 트레이싱 | 9 |

→ **외부 인증 / 모니터링 SaaS 의존 없음**. self-hosted 철학.

## 다른 솔루션과의 차이

| | LangChain | LiteLLM | **TokForge** |
|---|---|---|---|
| 위치 | 라이브러리 (앱에 탑재) | API 게이트웨이 | **에이전트 ↔ LLM 사이 미들웨어** |
| 자동 RAG | 구성 필요 | 미지원 | **모든 채팅에 자동 적용** |
| 의미 캐시 | RedisSemanticCache (외부) | 미지원 | **로컬 자체 구현** |
| 프롬프트 버전 관리 | 없음 (코드 변경) | 없음 | **DB + Admin UI (무재기동)** |
| 프로젝트별 분리 | 없음 | 없음 | **사용자 + 프로젝트 격리** |
| 모니터링 | LangSmith (유료/외부) | 자체 대시보드 | **로컬 SQLite + Admin** |
| 외부 의존 | 없음 (라이브러리) | 호스팅 가능 | **완전 self-hosted** |

→ TokForge 는 **"개인/팀의 프로젝트별 AI 컨텍스트를 최적화하는 self-hosted 미들웨어"**.
범용 라이브러리가 아니라, "프로젝트별 컨텍스트 튜닝"이라는 한 가지 시나리오에 집중.

## 현재 단계의 학습 가치

이 프로젝트는 단순 도구가 아니라 **Python + AI 인프라 + Full-stack 학습 코스** 로도 설계됨:

| 단계 | 배우는 것 |
|---|---|
| 1 | FastAPI · async/await · Pydantic · OpenAI 호환 API |
| 2 | 임베딩 · 벡터 DB(FAISS) · 코사인 유사도 |
| 3 | 청킹 · 검색 증강 · 프롬프트 컨텍스트 주입 |
| 4 | 프롬프트 엔지니어링 · 템플릿 추상화 |
| 5 | LLM 의 LLM 활용 (질문 자체를 LLM 으로 다듬기) |
| 6 | 토큰 경제 · 컨텍스트 압축 알고리즘 |
| 7 | 멀티 모델 라우팅 · 비용/성능 트레이드오프 |
| 8 | 옵저버빌리티 · 시계열 분석 · SQLite 집계 |
| + | OAuth 2.0 + PKCE · 세션 관리 · 격리 보장 · React Context |
