# 1. 프로젝트 개요

## 한 줄 정의

> **TokForge — VSCode + Continue.dev 와 AI 백엔드(로컬 Ollama / 외부 API) 사이에서 동작하는 로컬 미들웨어.
> 질문을 자동으로 캐싱·정제·규격화·압축하고 컨텍스트를 보강하여, 더 적은 토큰으로 더 정확한 답변을 받는다.**

> **토큰 절감 = 외부 API 면 비용, 로컬 LLM 이면 속도·자원**.
> 백엔드와 무관하게 가치를 만드는 것이 TokForge 의 설계 원칙.

## 미션

> 프롬프트를 최적화하여 토큰을 절감하고 답변 정확도를 높이며,
> 흐름과 통계 시각화로 지속 개선한다.

---

## 왜 만드는가 — 문제 정의

| 현재 AI 코딩 워크플로의 문제 | TokForge 의 해법 |
|---|---|
| 같은 질문을 매번 새로 호출 → 토큰 낭비 | **의미 캐시** — 비슷한 질문 즉시 응답 |
| 회사 코드/문서 컨텍스트 없음 → 환각 | **RAG** — 사내 문서 자동 검색·주입 |
| 프롬프트 품질 들쭉날쭉 → 답변 불안정 | **템플릿화** — 일관된 형식 강제 |
| 짧고 모호한 질문 → 헛다리 답변 | **질문 정제** — LLM 으로 의도 명확화 |
| 긴 컨텍스트 → 토큰 비용 폭증 | **압축** — 핵심만 추출 |
| 모든 질문에 비싼 모델 사용 → 과지출 | **모델 라우팅** — 복잡도 따라 자동 선택 |
| 토큰/비용 가시성 부족 → 개선 불가 | **모니터링** — 흐름·비용·품질 시각화 |

```
    ↓
[4] 압축                      핵심만 남기고 토큰 줄이기
    ↓
[5] 프롬프트 조립              템플릿 + context + 질문
    ↓
[6] 모델 라우팅                복잡도 → OpenAI / Anthropic / Gemini / Ollama
    ↓
[API 호출]
    ↓
[응답]
    ↓
[7] 캐시 저장 + 통계 기록      모니터링 데이터 누적
    ↓
[사용자]
```

## 아키텍처

### 전체 위치

```
┌─────────────────┐       ┌──────────────┐       ┌──────────────────┐
│  VSCode         │       │  TokForge    │       │  AI Backend      │
│  + Continue.dev │ ────▶ │  (FastAPI)   │ ────▶ │  Ollama / 외부 API│
│  (port: -)      │       │  port: 8000  │       │  port: 11434 / -  │
└─────────────────┘       └──────────────┘       └──────────────────┘
                                 │
                                 ▼
                          ┌──────────────┐
                          │  로컬 저장소  │
                          │  cache.db    │
                          │  rag.db      │
                          │  *.faiss     │
                          └──────────────┘
```

### 백엔드 레이어 (Layer 책임 분리)

```
TokForge/
├── main.py                     진입점 (FastAPI 앱 + 라우터 등록)
└── app/
    ├── config.py               전역 설정값
    ├── api/                    🌐 HTTP 인터페이스 (Java Controller)
    │   ├── health.py
    │   ├── chat.py
    │   ├── models.py
    │   ├── cache.py
    │   └── rag.py
    ├── services/               🧠 비즈니스 로직
    │   ├── cache.py            의미 캐시
    │   └── rag.py              문서 검색
    └── llm/                    🤖 외부 LLM 호출
        └── ollama.py
```

| 레이어 | 책임 | Java 비유 |
|---|---|---|
| `api/` | HTTP 경로 + 요청/응답 변환 | Controller |
| `services/` | 핵심 로직 (캐시·검색·정제) | Service |
| `llm/` | 외부 LLM API 호출 | RestClient / Repository |

→ 한 메뉴를 수정할 때 **세 레이어만** 보면 된다 (api → service → llm).

## 주요 의존성

| 라이브러리 | 용도 | 단계 |
|---|---|---|
| `fastapi` + `uvicorn` | 웹 서버 | 1 |
| `httpx` | Ollama 호출 | 1 |
| `sentence-transformers` | 문장 → 벡터 임베딩 | 2 |
| `faiss-cpu` | 벡터 유사도 검색 | 2 |
| `aiosqlite` | 비동기 SQLite (예약) | 2 |

→ **랭체인/랭그래프 의존 없음**. 학습 + 가벼움 + 디버깅 용이성을 위해 핵심 기능을 직접 구현.

## 다른 솔루션과의 차이

| | 랭체인 | LiteLLM | **TokForge** |
|---|---|---|---|
| 위치 | 라이브러리 (앱에 탑재) | API 게이트웨이 | **VSCode ↔ AI 사이 미들웨어** |
| 자동 RAG | 구성 필요 | 미지원 | **모든 채팅에 자동 적용** |
| 의미 캐시 | RedisSemanticCache (외부) | 미지원 | **로컬 자체 구현** |
| 모니터링 | LangSmith (유료/외부) | 자체 대시보드 | **로컬 시각화 (예정)** |
| 외부 의존 | 없음 (라이브러리) | 호스팅 가능 | **완전 로컬** |
| 학습 가치 | 블랙박스 | 블랙박스 | **레이어가 모두 보임** |

→ TokForge 는 **"VSCode 사용자의 코딩 워크플로 전용 최적화 게이트웨이"**.
범용 라이브러리가 아니라, 한 가지 시나리오(IDE 코드 어시스턴트)에 집중.

## 현재 단계의 학습 가치

이 프로젝트는 단순 도구가 아니라 **Python + AI 인프라 학습 코스** 로도 설계됨:

| 단계 | 배우는 것 |
|---|---|
| 1 | FastAPI · async/await · Pydantic · OpenAI 호환 API |
| 2 | 임베딩 · 벡터 DB(FAISS) · 코사인 유사도 |
| 3 | 청킹 · 검색 증강 · 프롬프트 컨텍스트 주입 |
| 4 | 프롬프트 엔지니어링 · 템플릿 추상화 |
| 5 | LLM 의 LLM 활용 (질문 자체를 LLM 으로 다듬기) |
| 6 | 토큰 경제 · 컨텍스트 압축 알고리즘 |
| 7 | 멀티 백엔드 · 비용/성능 트레이드오프 |
| 8 | 옵저버빌리티 · 시계열 분석 · 시각화 |
